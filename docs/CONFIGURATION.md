## 2. Environment Variables (Windows)

Set as **user** environment variables:

```powershell
# JDK 21 (Android Studio bundled JBR)
[Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Program Files\Android\Android Studio\jbr", "User")

# Android SDK
[Environment]::SetEnvironmentVariable("ANDROID_HOME", "$env:LOCALAPPDATA\Android\Sdk", "User")
[Environment]::SetEnvironmentVariable("ANDROID_SDK_ROOT", "$env:LOCALAPPDATA\Android\Sdk", "User")

# Add adb/emulator to PATH
[Environment]::SetEnvironmentVariable("PATH", "$env:PATH;$env:LOCALAPPDATA\Android\Sdk\platform-tools;$env:LOCALAPPDATA\Android\Sdk\emulator", "User")
```

> Note: session-scoped changes (set in a terminal) don't survive a reboot. Persist via `-Scope User`, then open a **new** terminal so the values take effect.

## 4. JDK 21 & Gradle Toolchain

The project uses a **JDK 21 toolchain** (default for React Native 0.85 via the RN Gradle plugin). Two things configure this:

**a) Gradle daemon JVM** — `android/gradle/gradle-daemon-jvm.properties` (generated by Android Studio):

```properties
toolchainVendor=ORACLE
toolchainVersion=21
```

**b) Foojay toolchain resolver** — `android/settings.gradle` includes:

```groovy
id 'org.gradle.toolchains.foojay-resolver-convention' version '1.0.0'
```

This lets Gradle auto-provision missing JDKs. **Do not** set `react.internal.disableJavaVersionAlignment=true` in `gradle.properties` — React Native's plugin uses that flag to disable its built-in JDK-21 toolchain alignment and the build then fails with *"Inconsistent JVM-target compatibility detected"*.

**c) Fallback daemon home** — `android/gradle.properties`:

```properties
org.gradle.java.home=C:/Program Files/Java/jdk-21.0.11
```

This is only used when Android Studio's daemon JVM config is absent; keep both consistent at JDK 21.

## 6. gradle.properties

Key settings in `android/gradle.properties`:

```properties
org.gradle.jvmargs=-Xmx4096m -XX:MaxMetaspaceSize=1024m
android.useAndroidX=true
reactNativeArchitectures=armeabi-v7a,arm64-v8a,x86,x86_64
newArchEnabled=true
hermesEnabled=true
org.gradle.vfs.watch=false
```

- `newArchEnabled=true` — New Architecture (Fabric/TurboModules).
- `hermesEnabled=true` — Hermes JS engine.
- `org.gradle.vfs.watch=false` — disables Gradle file-watching, which avoids a Windows file-lock error (`dependencies-accessors` move failed) that occurs on this machine.

## 9. Troubleshooting

### "Inconsistent JVM-target compatibility detected for tasks 'compileDebugJavaWithJavac' (1.8) and 'compileDebugKotlin' (21)"

Cause: mixed Java/Kotlin JVM targets across modules. Fix: ensure `react.internal.disableJavaVersionAlignment=true` is **absent** from `gradle.properties` so the RN plugin aligns every module to JDK 21. Do not add per-module `compileOptions`/`kotlinOptions` — that re-triggers the mismatch.

### "Unable to locate NDK" / NDK download keeps resetting

Download the NDK manually and unpack so that `ndk\27.1.12297006\source.properties` exists (no extra nesting). Remove partial `*.zip.part` downloads from the SDK `ndk` folder.

### Gradle "Connection reset" downloading from services.gradle.org

Use the local wrapper distribution (Section 5). Keep `gradle-wrapper.properties` pointing at the local file URL until the network is reliable.

### "The value for property 'languageVersion' is final and cannot be changed any further"

Caused by a manual `jvmToolchain(21)` in `allprojects`/`subprojects` config after evaluation. Remove all hand-written toolchain config; rely on the RN plugin + `gradle-daemon-jvm.properties`.

### `dependencies-accessors` move failed (Windows file lock)

Add `org.gradle.vfs.watch=false` to `gradle.properties` (already set).

### adb: command not found

Add `%ANDROID_HOME%\platform-tools` to `PATH` (Section 2) and ensure an emulator is running (`emulator -list-avds`, then launch one; `adb devices` should list `emulator-5554`).
